## 1. 实现与评审边界

用户已授权正式开发，本次七项确认替换旧版资源/工位、完成时间及行前插单规则。本文描述最新目标交互；[可运行界面稿](./index.html)仍是 1.4 历史演示，包含旧工位、完成时间、前插及不顺延逻辑，尚未按 2.0 改造，不能据此验收新功能。原型没有真实请求，不作为生产页面兜底。

V9 已提供生产计划基础 CRUD、资源产线映射和产线主工序配送区配置。两个配置对象的正式页面与基础资料原型已实现，入口为产线行“关联配置”。生产计划专用导入、模板、插单、调序、变更记录及关联任务接口仍未提供，不能用普通新增/更新模拟其业务语义。

正式生产计划查询页现已实现，组件路径 `/business/production-plan`，由用户配置菜单。当前仅接入真实分页与产线/配送区名称查询；写操作、变更记录与任务功能因缺少契约/资格依据未开放。下文为完整目标，实际阶段范围见 SPEC 第 17.10 节，不将禁用入口视为功能已实现。

## 2. 已确认业务

| 事项 | 当前结论 |
| --- | --- |
| 计划身份 | planNo 独立且唯一，保留 orderNo；页面可以订单号为主要信息，操作始终指向具体计划 |
| Excel 资源 | 独立 resourceCode，通过配置映射物流产线 productionLineId，不等同产线或工位 |
| 配送范围 | 物流产线 + mainProcessCode 唯一确定 deliveryStorageZoneId；区内允许多个接驳位置 |
| 筛箱与选址 | Excel 确定配送范围，MES 下道工序筛选合格料箱；后端在区内选择服务产线且用途、规格符合的位置 |
| 时间 | 不需要预计/计划完成时间；预计自动触发时间 = 计划开工时间 − 系统配置的提前分钟数 |
| 数量 | 正整数，不展示计量单位 |
| 插单 | 位于符合条件的目标计划之后，后端顺延同 resourceCode 下后续未执行计划；资格及原因由后端返回 |
| 调序范围 | 同一 resourceCode，不按物流产线或主工序分组 |
| 日期默认 | 初次进入及重置为当天 |
| 导入 | 选择文件直接上传，后端返回成功或失败；无预览和确认导入步骤 |
| 模板 | 点击直接调用后端并下载文件，无预览弹窗 |
| 查看 | 变更记录、关联 AGV 任务分别使用独立弹窗 |

planNo、orderNo、资源和主工序编码按文本保留前导零。不得按 orderNo 合并不同计划；选择用 id，写操作按具体计划及版本提交。后端校验 planNo 唯一性及其他重复规则，前端不去重覆盖。

## 3. 页面与查询

沿用工业管理台白色面板、青绿主色、紧凑查询区、标题工具栏、表内滚动和右下分页，不新增装饰统计或说明横幅。普通弹窗最大 760px、确认 460px；两列表单间距 12px/16px；沿用设计指南的主题、无障碍和提交反馈。

查询区分订单号、资源编码、物流产线、主工序、配送存储区、计划开工日期及状态；字段使用 V9 查询契约，常用/更多条件按正式页面紧凑布局组织。移除工位选择及旧线体工位联动。日期重置恢复当天并清空其他条件；时间边界以最终业务时区/契约为准，不用 UTC 日期截断。

查询、重置及翻页清空选择，查询回第一页，刷新保持已应用条件；防止迟到响应覆盖新结果。后端分页默认 20 条；仅为支持的可见字段提供表头排序，不改变业务排程。

列表展示计划顺序、生产订单号、planNo、数量、资源编码、物流产线、主工序、配送存储区、开工时间、预计自动触发时间、状态、关联运输任务数及操作。订单号可作为主要信息，但 planNo 必须可辨别，不以行号代替业务顺序。不显示完成时间或一个虚构的固定工位；任务目标位置由后端实际分配。

顶部保留模板下载、Excel 导入、调整顺序、刷新；行内保留变更记录、修改、插单、删除，无行调序或顶部插单。当前阶段仅刷新可用，其他入口禁用并支持悬停/聚焦查看原因；没有返回的任务数及预计时间显示“—”，不编造 0，不开放任务弹窗或行勾选。

正式查询页常用条件为订单号、资源编码、开工日期和后端计划状态；计划单号、主工序、产线与配送区收纳在更多条件。日期沿用现有系统 Asia/Shanghai 基线，使用带 +08:00 的全天边界；最终业务时区和后端边界语义仍待联调。表头排序仅开放计划顺序、计划单号和开工时间。

## 4. 状态与操作边界

| 后端状态 / 条件 | 页面状态 |
| --- | --- |
| PLANNED，当前时间早于预计自动触发时间 | 未到配送时间（灰蓝） |
| PLANNED，当前时间达到或超过预计自动触发时间 | 待配送（蓝） |
| EXECUTING | 配送中（青绿） |
| COMPLETED | 配送完成（绿） |
| CANCELLED | 配送异常（红） |
| 未知，或 PLANNED 的触发时间依据缺失 | 状态待确认（中性，保留原始值） |

PLANNED 两个阶段不是新的后端枚举，状态筛选不得将展示文字传给 planStatus，也不能仅过滤当前页冒充全局筛选。触发时间公式已明确，但有效配置、服务器时间/业务时区及前端展示计算方式尚需落实，不能硬编码提前量。任务状态与计划状态分开处理，不从任务数或完成比例推断计划状态。

修改、删除及调序暂沿用仅“未到配送时间”可维护，待配送即使无任务仍禁用；提交时后端重校验。插单资格及原因由后端返回，不能额外根据旧统一矩阵排除或放行 EXECUTING；资格缺失、失败或拒绝时禁用并说明原因。禁用原因支持悬停和键盘聚焦，具体资格字段尚待接口提供。

## 5. 导入与模板

Excel 采用独立资源编码和主工序确定配送范围，不要求指定工位或完成时间。planNo 在模板填写还是后端生成待明确。后端校验数量、时间、映射配置、计划标识及重复数据。

选文件后直接上传，期间禁用并转圈、禁止重复进入和关闭，不表现为取消后端处理。成功展示后端真实返回消息/条数并刷新；失败保留文件名和错误信息，安全展示实际返回的明细，不编造统计、回滚或部分成功。网络中断/超时提示结果未知，不自动重传。

模板下载复用鉴权与文件下载方法，按钮请求期间禁用并转圈。使用服务端文件名，识别 JSON 业务错误，不保存为 Excel，适时释放 Blob URL。不增加预览弹窗。

## 6. 修改、行后插单与删除

修改关注 orderNo、正整数数量、资源编码、主工序和计划开工时间；数量原值与标签同行。无完成时间字段和开始/完成比较校验。planNo 的生成/可改规则待确认；物流产线、配送区依配置由后端解析，配送区只读，前端不手选接驳位置。

插单从具体目标计划行进入，仅提示“插入到计划 {planNo}（订单 {orderNo}）之后”，方向固定，无方向选择器。固定目标 resourceCode，主工序继承及其他输入由新插单契约确定，不能恢复旧工位输入。后端校验目标资格及版本，顺延同资源后续未执行计划，前端不计算顺延值或批量写其他计划。目标失效保留输入并展示原因。

删除标题“删除确认”，正文“是否确认删除生产计划单：{planNo}（订单 {orderNo}）”，仅取消/确认删除。成功后刷新，失败不提前移除行；删除不等于取消 AGV 任务。

## 7. 单选/多选调序

保留复选框、至少一条及顶部调序按钮，无行按钮、上移/下移或结果预览。所选计划要求未到配送时间且 resourceCode 相同；资源缺失禁止调序，即使产线/主工序相同也不能跨资源操作。

第一条选择限定其余可选项，全选仅作用当前页同资源可调项；候选目标为同 resourceCode、未到配送时间且不在所选组内的另一条计划，不受主列表当前分页或其他筛选截断。

弹窗只含目标计划、放置位置、所选计划和取消/保存。独立调序暂保留默认之前、可选之后，本次行后插单规则不自动改变调序方向。组内保持原业务顺序，影响范围为同一资源；是否顺延时间仍需确认，不再承诺所有时间不变。

无目标/无变化不能保存；后端重新校验所选、目标及受影响范围，不能静默剔除失效项提交其余项。保存成功以后端结果刷新，不使用本地数组换序作为正式实现。

## 8. 记录、任务与反馈

变更记录只展示该计划的变更时间、操作人、动作、前后值及必要来源，按时间倒序；任务弹窗仅展示该计划实际关联任务的编号、状态、目标位置、创建时间及异常原因。不按订单号跨计划合并，不提供综合详情抽屉或未定义的取消/重建。

0 任务仅在后端真实返回 0 时展示为空态；加载、空记录和失败分开，失败可重试，长内容表内滚动或按契约分页。所有非查询按钮提交期间禁用并转圈，函数防重复。失败保留输入；409/40900 使用“数据已被其他操作修改或删除，请刷新后重试”，不得自动覆盖或重试。

## 9. 验收与待确认

新版本验收应覆盖：同订单不同计划不串操作；编码前导零；资源产线映射与唯一配送区；同区多位置不在计划表单强制选定；无完成时间；PLANNED 触发前、恰好到达、超时及配置缺失；其他三状态；后端插单资格允许/拒绝/缺失、行后插单及同资源未执行计划顺延；导入/下载/冲突反馈；调序同资源选择及跨资源禁选（即使产线相同）；独立记录/任务弹窗。

待确认：planNo 生成与可修改性；提前量配置键及有效值/时间来源；PLANNED 两阶段查询；插单资格/原因的具体字段、主工序等继承字段、同资源顺延算法；独立调序是否顺延；跨范围修改；专用操作、记录与任务接口及分页/事务定义。资源隔离及由后端返回插单资格已确认。所有后端合同补齐前不编造接口。

本次交付正式查询页，未修改 1.4 可运行原型；旧 `verify.mjs` 只验证历史原型，不能作为上述新规则的验收。当前正式页的本地验收覆盖筛选/排序/分页、日期、身份与状态回显、不可用操作边界和失败反馈，完整维护验收待缺失契约补齐。真实浏览器与后端验证由用户进行，未经再次明确要求不运行真实浏览器自动化。
