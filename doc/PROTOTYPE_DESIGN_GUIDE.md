# 页面原型设计指南

版本：1.0 · 更新日期：2026-09-16

适用范围：工业系统管理平台及 V1-NARI-LES 的 PC 管理页面原型、新功能设计和统一风格调整。业务行为以 [SPEC](./SPEC.md) 为准；本指南规定默认表现，页面特例写入对应交互说明。本文是后续设计基线，不表示所有既有页面已完成样式迁移。

参考：[生产计划单原型](./prototypes/production-plan/index.html) · [交互说明](./prototypes/production-plan/interaction-spec.md)。

## 1. 设计原则

- 面向生产、计划及系统管理人员：信息密度适中偏紧凑、操作清晰、反馈可信，沿用工业管理台风格，不设计营销式大标题和装饰性指标卡。
- 先确认业务边界，再设计页面。状态、权限、重复规则、顺序及计算责任不从截图推断。
- 使用已有框架和组件；正式页面沿用 Vue 3、Ant Design Vue，不为单页另建样式体系或引入 UI 库。
- 文案只承担一个作用，去掉重复副标题、统计、长篇说明和技术实现提示；但不能删除风险提示、校验反馈或禁用原因。
- 紧凑靠合理间距和内容取舍，不靠缩小到难读的字体、截断关键字段或隐藏滚动条。

## 2. 设计前输入与交付

开始前明确：使用者、页面目标、字段及类型、查询条件与默认值、状态/操作矩阵、前后端职责、破坏性操作和并发风险。未确认项独立记录，不能写成既定功能。

按“需求确认 → 高保真可交互原型 → 用户评审 → 文档同步 → 正式实现”推进；未经确认不把原型直接当正式业务页面。

原型目录约定：`doc/prototypes/<页面>/`，至少包括：

- `index.html`：可打开的高保真界面。
- 交互脚本及必要的本地资源：可与 HTML 分离，避免外部资源影响评审。
- `interaction-spec.md`：版本、日期、业务链接、交互和状态说明、已取消设计、待接口确认项、验收场景。
- 有状态切换/校验等逻辑时，附最小可运行的本地检查，例如 `verify.mjs`。

演示场景切换器、模拟结果开关明确标为评审工具，不进入正式页面。示例数据隔离在原型目录，不接入生产页面，不用模拟成功冒充实际上传、下载或保存。

## 3. 视觉基线

以下颜色为浅色原型参考；正式工程通过统一主题 token 适配浅色/深色/跟随系统，不在单页硬编码覆盖所有主题。

| 用途 | 参考值 |
| --- | --- |
| 主色/链接/选中态 | `#0D9496` |
| 主文字 | `#233638` |
| 辅助文字 | `#77898D` |
| 页面底色 | `#EDF2F3` |
| 侧栏、顶部、标签栏、面板 | `#FFFFFF` |
| 分隔边框 | `#DCE5E7` |
| 错误/危险 | `#CE4E4E` |
| 成功 | `#218564` |
| 信息/警告 | `#4277BD` / `#A76A12` |

- 字体使用系统中文无衬线栈，如 PingFang SC、Microsoft YaHei、sans-serif，不下载公网字体。
- 参考字号：页面标题 19px，普通弹窗标题 17px，确认弹窗标题 16px，正文 14px，表格/字段标签 13px，辅助信息 12px；正文行高约 1.5。
- 长编号保留完整数据；数字可使用等宽数字特性，不为普通文本强制等宽字体。
- 面板与表格直角，包括表头四角和固定列容器；输入框/按钮可小圆角，弹窗可约 6px。正式主题配置变化需统一处理，避免局部冲突。
- 状态采用文字 + 颜色，不只靠颜色。未知值中性展示，不能伪装成成功。
- 图标沿用 Ant Design Vue 线框风格，不混用填充/双色图标；相邻关闭、固定等辅助图标尺寸及颜色统一。

## 4. 框架与空间

- PC 基准宽度 1440px，同时检查更宽屏幕和缩小窗口。不自动增加移动端需求。
- 侧栏、顶部、标签栏沿用现有应用框架；标签栏白底，标签为独立边框样式，选中浅青底，工作台固定不可关闭。
- 标签过多时标签栏内部横向滚动，不能挤出页面。标签右键提供刷新、关闭当前/其他/右侧等已有操作。
- 内容区撑满剩余高度；默认外边距上 8px、左右及底部 10px，区域间距 10px。
- 默认布局为“查询区 + 标题/操作区 + 列表 + 分页”。查询和工具栏保持可见，分页位于底部右侧。
- 页面不出现整体纵向滚动；长表格在表体内滚动，宽表格在自身横向滚动，不能靠压缩列宽造成内容重叠。
- 双表布局默认平分扣除间隙后的可用宽度，间距 10px：`grid-template-columns:repeat(2,minmax(0,1fr))`；不是两个 `50%` 再额外添加 gap。
- 双表标题、按钮与表头水平对齐，各自内容区独立滚动；使用 `min-width:0`、`min-height:0` 允许布局收缩。

## 5. 查询区与工具栏

- 常用条件直接展示，查询/重置在右侧对齐，刷新沿用该页面约定位置，不重复堆叠。
- 默认紧凑无上方标签，通过明确占位文案和当前值识别；仍提供 `aria-label` 或关联的隐藏 label，不能只依赖 placeholder。
- 输入/按钮约 34px 高，控件间距 8–10px。明确的业务默认值才预填，不把示例值推广为正式默认值。
- 联动条件切换后清空不再有效的下级值。起止日期校验、当天边界、时区以及重置规则写入页面说明。
- 页面标题和主要操作同行垂直居中。展开/收起等辅助操作位于工具栏，不掉到标题下一行。
- 默认不显示重复的标题条数、副标题、更新时间和排程说明横幅；确有工作必要时才加入。

## 6. 表格规范

- 参考尺寸：表头 42px，普通表体行 46px，单元格上下 8px、左右 12px；长内容允许合理增高，不能强制高度导致遮挡。
- 选择列单独固定最左侧，复选框水平/垂直居中，支持全选/半选；业务要求单选时另行确定，不把多选改为单选来简化实现。
- 操作列固定右侧。表头层级高于固定列的表体，背景不透明；检查横纵滚动交叉处不遮住表头/首行。
- 状态、标签和操作不溢出到相邻列。长文字用省略 + 可访问完整内容或安全换行；长枚举先按契约转换显示文案。
- 列设置入口与列标题垂直居中，不能依靠固定像素偏移偶然对齐。适用通用表格时沿用已有列设置组件：显隐、排序、固定、恢复默认、取消和确认。
- 表格查看排序与业务顺序分开；影响业务顺序的动作必须显式保存。选择按唯一 ID 关联，不使用行号。
- 空数据、请求失败与加载中分开。查询分页遵守真实接口，不把一页演示数据冒充服务端分页。

## 7. 弹窗规范

默认居中弹窗，不自动采用抽屉。只有明确需要持续对照主列表等工作场景并经确认时使用抽屉。

| 项目 | 普通表单/记录/任务弹窗 | 简单确认弹窗 |
| --- | --- | --- |
| 宽度 | 默认最大 760px，复杂表格按实际需要调整 | 默认最大 460px |
| 视口限制 | 不超过 `100vw - 40px` | 同左 |
| 标题字号 | 17px | 16px |
| 头部内边距 | 上 14px、左右 16px、下 10px | 同左 |
| 正文内边距 | 上下 14px、左右 16px | 16px |
| 底部内边距 | 上下 10px、左右 16px | 同左 |
| 按钮间距 | 8px，靠右对齐 | 同左 |

- 高度由内容决定，不设置造成大片空白的固定高度；最大高度留出视口边距。标题和操作区保持可见，正文独立滚动。
- 空副标题不占位。简单确认正文段落默认无额外 margin，长订单号可换行。
- 两列表单等宽，行距 12px、列距 16px，字段与控件间约 5px，输入高约 36px；跨列备注单独整行。
- 原值等短辅助信息可置于字段标签同行，避免为一句说明增加整行空间。不可编辑字段保留禁用态，不通过隐藏制造表单空洞。
- 提示条只保留必要目标、风险或错误，参考内边距 8px 10px、下间距 12px；禁止重复标题里的信息。
- 弹窗内表格表头约 32px、行约 36px，上下 6px、左右 10px；时间线条目间 12px。长内容须完整可访问。
- 查看弹窗只承担一个明确任务：记录归记录、关联对象归关联对象，不混入无关信息与操作。
- 简单删除默认一句“是否确认删除{对象}：{标识}”，底部取消/确认删除。额外影响说明仅在业务需要且已确认时添加；涉及联动删除、不可恢复后果时不能为简洁而隐瞒。

## 8. 操作反馈与安全边界

- 每个操作写清入口、适用状态、输入、校验、提交中、成功、失败和取消行为。
- 非查询请求触发按钮在请求期间禁用并转圈，处理函数也防止重复进入；不是延迟执行式“防抖”。查询显示加载和处理竞态，不冻结整个页面。
- 禁用操作提供原因，可由悬停与键盘聚焦获得；按钮禁用时不能继续执行 click 请求。
- 成功才关闭并刷新；失败保留输入，不能静默丢弃。取消草稿不能被表达为撤销已提交的后台任务。
- HTTP 409 / 业务码 40900 使用 SPEC 统一提示，保留草稿、重新获取状态后决定是否可提交，不自动覆盖最新版本或重试写入。
- 导入、下载、批量操作、顺序调整按各自接口设计，不能假定全部导入都需要预览或全部批量操作都部分成功。
- 业务和错误内容以文本安全渲染，不直接插入后端 HTML。正式权限与校验由后端兜底，演示场景删减不代表取消安全控制。

## 9. 统一风格调整方法

1. 列出受影响页面、组件、状态和用户明确指定的例外。
2. 优先调整共享 token 或组件，避免各页面叠加覆盖选择器；局部样式明确作用域。
3. 检查标题、按钮、输入、表头、固定列、弹窗等关联部件，不能只修一张截图上的静态位置。
4. 检查长文本、少量/大量数据、横纵滚动、空态、错误、禁用和提交中，防止紧凑化牺牲可读性。
5. 同轮更新本指南、SPEC 的相关视觉约定及受影响页面说明。区分已修改页面与未来设计规范，不宣称全站已统一。

## 10. 验收与文档同步

- 用户负责真实浏览器视觉验收；未经重新明确要求，不运行 Playwright 或其他真实浏览器自动化。
- 可执行静态检查、类型检查、单元测试及本地 DOM 检查；必须准确报告检查范围，DOM 通过不代表像素布局已验证。
- 检查表单标签、键盘焦点、弹窗关闭/焦点返回、禁用原因和状态文本。紧凑不应让按钮难以点击。
- 交付提供入口、说明、变更摘要、测试结果与未接入接口列表。演示数据与真实请求必须明确区分。
- 新增/变更/取消功能时更新 SPEC 正文和验收项；原型变更同时更新页面交互说明；通用视觉变更更新本指南。删除冲突旧规则，更新日期，文档随代码提交。

## 11. 生产计划单的明确特例

以下仅适用于该页面，不能误推广为所有页面业务规则：日期默认当天；直接上传返回结果；行前插单；调序支持一条或多条同资源工位计划；维护仅限未到配送时间；变更记录和 AGV 任务分别弹窗。

已取消的设计不得未经确认重新加入：综合详情抽屉、导入校验预览/确认步骤、顶部插单、行调序、调整结果预览、计划状态“部分完成”、无权限演示场景、标题附加计数/说明、排程范围横幅。
